## 本轮确认并修复的缺陷

1. DeepSeek thinking 历史继续调用缺失 `reasoning_content`，以及 thinking 模式不支持强制 `tool_choice`。
2. 完成的工具历史伪装成用户消息，导致模型续写虚构工具结果。
3. arXiv 工具完成后再次调用模型，出现空回答、失败或编造论文。
4. 单路线成功后再次模型总结，浪费时间且遗漏腾讯纠错证据。
5. 六站路线与日程完成后再次模型总结，编造与 Action 不一致的停留时长。
6. 能力规划器或降级工具模型会先改正用户地点错字，绕过腾讯证据。
7. 工作区 POI 缓存用字符串相似度冒充纠错证据。
8. 路线缓存丢失本轮纠错证据，或把旧纠错证据污染到本轮精确查询。
9. 日程固定 JSON 使用深度思考模型，六站中间阶段耗时过高。
10. 非必要旅行偏好被误路由到外部搜索，而不是先给假设方案。
11. 腾讯地点底层两次 8 秒重试被外层 8 秒超时提前取消，新地点搜索可能返回空或超时。
12. 单个短名称模糊工作区候选被静默视为唯一地点，导致“王府井”被旧餐馆候选污染。

## 剩余风险与下一轮建议

1. 浏览器宿主修复后，优先补 50 个 release blocker 中要求真实点击、Network、Console、刷新与截图的步骤。
2. CORE-09 首轮不使用工具时仍可能出现约 68 秒首 token；需要继续拆分普通回答模型与共享 Provider 排队指标。
3. `answer_complete` 后的 follow-up、记忆与机会识别仍会延长 HTTP 连接总时长，但不再阻塞可见回答；应在可观测性中分开统计。
4. TRAVEL-10 仍需真实骑行、不可达、配额不足与缓存 mode 隔离的 UI 证据。
5. READ-03/04/05 需要一份可公开、带已知答案的 PDF 样本才能做可信端到端验收。
6. 生图和腾讯会议需要明确授权的真实账号/配额窗口，不能用 mock 结果宣称生产通过。
