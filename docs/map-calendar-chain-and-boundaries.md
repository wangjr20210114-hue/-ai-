# 地图—日程调用链与能力边界

## 当前调用链

1. 浏览器在用户授权后取得 WGS84 定位，保存在前端内存中，10 分钟后失效。每次聊天只附带一份新鲜位置状态；能力规划模型只知道“可用/不可用”，看不到精确坐标。
2. LangChain `with_structured_output` 生成能力计划，冻结路线站点顺序、城市、交通方式、路线策略，以及是否使用当前位置。主模型通过 LangGraph `ToolNode` 调用严格 Pydantic schema 的路线工具。
3. 地点先查 Makers LangGraph Store 短缓存，再走统一的腾讯证据链：主地点搜索与“关键词输入提示”结果按 `place_id` 合并；只有主搜索没有精确证据时，建议结果才标记为纠错证据。日程副作用前执行固定三级决策：总共只有一个已核实候选时直接进入待确认提案；多个腾讯建议只在一次按需注入本组候选、使用 Flash 且关闭深度思考的结构化复核判定实际目的地近乎唯一时采用一个已提供的 `place_id`，否则保留腾讯同组相对顺序，并把请求中已有城市或候选一致城市对应的高概率候选移到主动式单选卡前面；无候选返回短文本填空卡。快速地图模式会跳过额外复核并采用 Provider 首选。这里不使用本地距离阈值、关键词、别名或编辑距离，未经用户选择的纠错结果不会跨对话复用。直接采用只跳过地点追问，不跳过日程最终确认。
4. OSM 只作为 POI 搜索兜底。浏览器和 OSM 的 WGS84 坐标先调用腾讯坐标转换服务变为 GCJ-02；道路匹配和驾车、公交、步行、骑行路线始终由腾讯完成。
5. 驾车多站一次传给腾讯；公交、步行、骑行的多站路线按相邻站点并发拆段后合计，严格保留用户顺序。默认策略使用腾讯 `LEAST_TIME` 和多方案，在最快耗时加用户设置容差内选择可核验费用最低者；明确“最省钱”的驾车路线还使用腾讯 `LEAST_FEE`。费用未知时回退最快，不声称最省钱。
6. 路线工具把可复用的 `route_plan_id`、核实地点、方式、策略和选择依据写入有界近期计划集，并生成需要用户点击的地图 Action。日程工具按来源 ID 和完整站点顺序确定性绑定地点；模型漏传地点 ID 或生成瞬时出发/抵达标记时，由路线协议补齐地点并采用日历最小正时长，不增加语义模型重试。另一个对话的新路线不会立刻覆盖当前提案；浏览器临时起点的持久记录不含地址或坐标。只在用户实际激活路线 Action 后统计其明确表达的方式和策略，并按 Action 去重；至少三次且某项占比达到 60% 才作为后续默认，设置中可以关闭学习。路线 Action 与日程 Action 独立；只有明确带未来时刻的多站行程或用户要求写入时，才另行生成可编辑、待确认的日程提案。
7. 日程确认前检查过去日期、重复项、时间重叠、相邻现实地点的腾讯路线耗时和用户缓冲。已核实路线中相同起止时刻的瞬时出发/抵达标记只规范为一分钟日历粒度并在卡片中提示，负时长、漏站或乱序仍拒绝。确认后通过 Makers Store 保存并触发主动提醒重算。

## 平台与业务责任

| 层 | 已复用能力 | 仍由项目负责 |
| --- | --- | --- |
| EdgeOne Makers | AI Gateway、Agent Runtime、Conversation Store、LangGraph Checkpointer/Store、Trace、Pages Blob、Schedule、GitHub Provider 部署 | 没有内置浏览器定位到 Agent 的绑定，也没有地图、路线、日程领域工具或业务事务语义 |
| LangChain / LangGraph | 结构化输出、Pydantic 工具 schema、ToolNode、RetryPolicy、checkpoint/store | 站点冻结、地点消歧、Action 确认、地图与日程独立/联动规则 |
| 腾讯位置服务 | 地点搜索、关键词提示、坐标转换、附近搜索、驾车/公交/步行/骑行、天气 | Provider 证据合并、语义消歧、缓存、超时、UI Action、跨段合计和错误呈现 |
| OSM | 腾讯搜索无可信结果时的 POI 搜索兜底 | 不用于道路匹配、ETA 或路线绘制 |

腾讯位置服务已有官方 MCP Server，能把原始 WebService 结果转成更适合模型理解的语义文本。当前项目暂不替换现有直连适配器：地图 UI 需要稳定 JSON、冻结 place snapshot、路线 polyline、精确缓存键和 60 秒硬截止；把它交给远程 MCP 的模型语义层会增加一次协议与模型不确定性。若 EdgeOne Agent Runtime 后续提供受管 MCP 工具注册、结构化原始 JSON 和可观测配额，适合在适配层增加可切换实现，而不是改动业务链。

## 仍然存在的边界

- 未授权、被拒绝、精度差于 5 公里或超过 10 分钟的浏览器位置不会作为起点；此时必须要求起点，不能用 IP 城市中心冒充当前位置。
- 腾讯地点搜索和关键词提示都没有足够证据时，系统只能澄清，不能保证恢复任意错字、旧地名、口语简称或新开店。
- 公交结果依赖当前运营时段和账号接口配额。腾讯支持 `departure_time`，但当前对话路线尚未把未来出发时刻传入公交/未来驾车接口，因此未来 ETA 仍是下一优先级。
- “省钱”只在腾讯实际返回且项目能核验的候选费用间比较。驾车自驾成本含真实距离、路桥费和通用能耗估算；公交使用腾讯票价；停车费、动态打车加价和城市优惠仍可能改变实际费用。
- 非驾车多站是相邻路段合计，不是跨全程换乘优化；公交各段票价相加也可能与城市封顶、联程优惠不同。
- 步行/骑行跨海、跨境、距离过长、道路吸附范围外或服务未覆盖时会失败；不会降级成驾车或直线距离。
- 腾讯 Key 未启用对应 WebService、QPS/PV 用尽、网络超时、响应缺少路线，都会在 60 秒内显式失败。OSM 不会接管道路计算。
- 日程时区当前固定为 Asia/Shanghai；跨时区旅行、航班动态、实时公交到站、无障碍路线、室内导航、车牌限行和未来路况尚未进入统一业务 schema。
- Makers Store 适合当前个人单用户工作区；如果扩展为多人同时编辑，需要更强的条件写入/事务与冲突合并策略。

## 自动化与发布门槛

- Python 契约测试覆盖当前位置新鲜度、语义路线方式、腾讯证据纠错、WGS84 转换、公交票价/步行接驳/polyline 和不同方式的缓存隔离。
- 前端测试覆盖单次位置内存、路线方式请求、路线 Action 状态与普通地点推荐的独立性。
- `/test-cases/` 的 `TRAVEL-08` 至 `TRAVEL-12` 覆盖真实对话边界：当前位置、错字三级决策、日程地点副作用、四种交通方式、省时/省钱策略、偏好学习、多站与不可达。
- 发布前运行 Python、前端、Cloud Functions、lint、i18n 和 production build；部署后再对 `floris.jlutx.com` 执行只读/低副作用对话冒烟。
