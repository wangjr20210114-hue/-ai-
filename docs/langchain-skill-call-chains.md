# Floris 全 Skill LangChain 调用链审计

更新日期：2026-07-26

## 共同入口

所有自然语言请求先进入 `/chat`，但不会再走一条固定的“大一统”链。

1. 只读取每轮必需的用户能力开关、预算和设置。
2. 普通请求使用两级关闭深度思考的 Flash 结构化链。
   - 第一级 `SemanticPreflight` 在同一次结构化调用中检查任务依赖，并按完整语义选择本轮需要的
     `web / maps / calendar / image / paper / meeting / proactive` 提示词片段；若缺少会阻断所有
     安全结果的必要输入，同时输出最小主动卡片 schema。
   - 仅当第一级准备发阻断卡时，增加一次独立 `ClarificationReview` 语义审查；只有审查确认
     “所有安全有用结果都被阻断”才立即结束。若卡片询问的是可默认偏好、账户、Provider 或实现细节，
     审查器会驳回并继续能力规划，不使用词表白名单。
   - 第二级只读取第一级选中的详细边界，输出完整 `CapabilityPlan`。
   - 两级都使用 LangChain `with_structured_output`；代码不以关键词、正则或固定短语决定 Skill。
3. 只为选中的能力加载 Workspace 或主动服务状态，只向 LangGraph 暴露当前工具和全局
   `ask_user_clarification`。
4. 固定 JSON、工具参数、Action 文案和普通总结默认使用关闭深度思考的 Flash；只有规划器明确
   `needs_deep_reasoning=true` 的开放式多步推理才使用主推理模型。
5. “猜你想问”、长期记忆提取、主动机会判断分别由
   `needs_followups / needs_memory_extraction / needs_opportunity_review` 控制，不再每轮无条件运行，
   且都使用 Flash。

语义预检失败时会附加全部片段以保证完备性，不会退回词表猜测；能力规划器超时时，只根据第一级
模型选择的主题开放有界恢复工具集。

### 规则与语义模型的边界

- 提示词片段、能力组合、当前位置语义、附近类别、路线站点和缺失必要信息均由结构化模型输出。
- 工具层只保留 schema、枚举、数量上限、坐标新鲜度和 Provider 返回值验证；这些是协议/安全校验，
  不承担自然语言意图判断。
- 地点错字和同名不由本地相似度或短语表纠正，原始站点文本直接交给腾讯地点证据链。
- 天气风险、线上/现实日程地点、论文意图和 PDF 内容类型不再由本地词表判断：天气使用独立
  Flash 结构化语义门，日程地点类型使用模型输出的协议枚举，任意 PDF 都可进入助读。
- HTML/JSON/ISO 日期解析、坐标范围、权限状态、工具名、Provider 状态和数量/超时上限仍由代码校验；
  它们只解释机器协议，不从自然语言推断用户意图。

## 1. Core 核心对话

调用链：

`用户消息 → Flash 必要输入门 + 动态提示检索 →（仅候选阻断卡：Flash 独立审查）→ Flash 能力规划 → Flash 普通回答或按需主推理模型`

- 普通知识、写作、翻译、总结不加载地图或日程 Workspace。
- `ask_user_clarification` 始终可用，因此缺少真正必要信息时，写作、翻译、文档问答等普通场景
  也能生成统一主动式卡片。
- 规划器若判定缺少不可替代输入，必须同时输出卡片标题、原因和最小字段 schema，系统直接调用
  `ask_user_clarification`，不再依赖最终回答模型自行选择是否发卡。
- 能采用安全默认值或给出多套假设方案时不得发卡。
- 长期记忆只有在规划器判定与本轮直接相关时才进入回答提示词。

## 2. Web Search 联网搜索

调用链：

`Flash 能力规划（合并一个查询） → rich_search 直接调用 → SearchPro → 可选并行媒体审核 → Flash 综合`

- 已规划的查询直接调用 `rich_search`，不会再让第二个模型复述同一搜索参数。
- 同一轮 `rich_search` 最多一次。
- 只有时效事实、用户要求查证/来源或现实世界信息才搜索。
- 图片有明确理解价值且用户的图片数量设置大于 0 时才启动媒体链。
- `collect_page_images` 和 `analyze_images_parallel` 保留为内部/兼容原语；正常成功规划不会把它们
  作为额外模型阶段暴露。

## 3. Vision 视觉理解

调用链分两类：

- 用户附图：`存在附图且 Vision 已开启 → 多模态 Provider 一次描述 → 能力规划/回答`
- 搜索图片：`rich_search 返回候选 → 有图片需求时并行视觉审核 → 回答`

无附图、搜索结果无图片价值或 Vision 关闭时，不调用视觉 Provider。视觉事实会作为不可信文档之外的
独立运行时片段注入，失败时明确说明未识别，不伪装看见。

## 4. Image Studio 图片工坊

调用链：

`Flash 能力规划 →（仅现实主体且无参考图时 rich_search）→ Flash 生成固定工具参数 → propose_image → 生图 Provider → 图片 Action`

- 原创、幻想或已有参考图时跳过联网搜索。
- 生图不增加“是否确认”模型轮次，直接生成；修改历史图会带 `parent_action_id`。
- 提示词翻译和 Provider 调用是生图适配层，不由深度推理模型处理。
- 最终图片只由图片工坊 Action 展示，正文不重复插图。

## 5. Maps 地图、地点与路线

### 当前位置

`Flash 语义提示选择 → Flash 能力规划 → location_request 事件 → 浏览器原生定位 → 自动重试原目标 → 腾讯逆地址解析`

前端不再用中文短语表猜测是否需要定位。能力规划器判定本轮需要浏览器位置后，前端才请求原生权限；
成功后不重复用户气泡并自动重试，拒绝、12 秒超时或设备不可用时生成对应原因的主动式填空卡。

### 附近搜索

`浏览器位置或用户填写锚点 → recommend_nearby_places_on_map → 腾讯附近检索 → 地图 Action → Flash 总结`

公共 OSM 不参与路线或地点匹配；它只可作为腾讯地点搜索服务的缓存层。当前坐标不会写入长期记忆、
日程或网页搜索词。

### 多地点推荐

`Flash 能力规划 → recommend_places_on_map → 腾讯逐点核实 → 单个地图 Action → Flash 总结`

组合工具内部完成逐点核实，不再额外暴露 `search_places_batch → prepare_map_recommendation` 两个模型阶段。

### 路线

`结构化有序站点 → 腾讯并行核实地点 → 各相邻路段并行规划 → 保序聚合 → 地图 Action → 本地固定总结`

- 结构化规划器已经给出完整 `route_stops` 时，LangGraph 直接调用路线工具，不再让第二个模型重写 JSON。
- 使用浏览器当前位置作为隐式起点时，工具先接收规划器的有序目的地，再以协议字段追加当前位置；
  后续模型交接不能覆盖该起点。
- 路线状态用 `implicit_browser_origin` 标记该临时起点；它参与腾讯路线计算，但不会进入可复用地点
  缓存。日程卡可以保留“从当前位置出发”的时间提醒，但在 Action 层会剥离临时地点对象、地址与
  坐标，只把用户要去的真实目的地作为日程地点。
- 相邻路段可并行，但最终结果严格按用户顺序聚合。
- 驾车、公交、步行、骑行由腾讯路线能力返回；默认策略是省时优先、时间相近选省钱。
- 精确地点或腾讯建议服务唯一候选直接继续。多个非精确候选只在此时增加一次关闭深度思考的
  Flash 语义裁决：若它们是同一明确地标的主地点、广场、出入口、站点等记录，且存在近乎确定的
  主 POI，就采用腾讯返回的该候选并披露纠正；若是不同分店、不同城市或独立场所，才按实际起点、
  终点或中途站编号发单选卡。这里不使用编辑距离、关键词、别名表或本地地点映射。
- 腾讯与公共地点搜索缓存都未能在时间预算内给出足够证据时，按同一站点标识发填空卡；必需的
  路线工具失败后会立即终止后续日程工具，最终模型不能用自由文本猜测路线或地点。

## 6. Calendar 日程

调用链：

`Flash 能力规划 → 按需加载当前 Workspace →（现实地点未核实时腾讯地点核验）→ Flash 生成变更 schema → propose_calendar_changes → 用户确认 Action`

- 只读日程不会生成写入 Action。
- 新增、更新、删除必须经过确认卡，模型不能直接落库。
- 路线与日程保持独立：多站路线先核实，随后只生成一张可编辑日程提案卡（卡内可含多个按站点
  排序的变更）；用户可单独查看路线或确认日程。
- 缺少不可替代时间/对象时使用全局澄清卡；仅地点模糊时先查腾讯候选，不提前追问。

## 7. Proactive Agent 主动服务

调用链分两类：

- 用户明确创建持续流程：
  `Flash 能力规划 → Flash 工作流参数 → propose_workflow → 用户确认`
- 回答后的主动机会：
  `CapabilityPlan.needs_opportunity_review=true → Flash 机会判断 → 去重/频控 → 主动提醒`

回答后机会判断、最近问题读取和记忆扫描不再每轮启动。页面打开时的记忆窗口检查只在主动 Skill 开启、
存在安全记忆且窗口到期时执行。

## 8. Paper Reading 论文助读

调用链：

- 纯论文/arXiv 检索：`Flash 能力规划 → search_arxiv 直接结构化调用 → 论文卡片 → 本地固定提示`
- 跨来源综述：`Flash 能力规划 → rich_search → search_arxiv（需要可下载论文时）→ 论文卡片/Flash 综合`
- 已上传论文：`文档解析 → reader 的当前 action 专属提示词 → Flash/配置模型 → 助读结果`

每个 reader action 只选 `translate / summarize / explain / questions` 中当前一个提示词，不混入其他动作。
翻译、摘要、术语、公式解释关闭深度思考并使用 Flash；只有整篇结构分析和基于论文的复杂问答使用
推理模型。纯 arXiv 卡片成功后不再调用模型生成一句固定确认文案。

## 9. Tencent Meeting 腾讯会议

调用链：

`Flash 能力规划 → 按需加载日程上下文 → Flash 生成会议提案参数 → propose_meeting → 用户确认 → 腾讯会议官方 MCP Skill`

- 会议依赖 Calendar；Token 或 Skill 不可用时不模拟成功。
- 主题或时间不完整时由可编辑会议确认卡补齐，不连续生成多轮自然语言追问。
- 真正创建会议和关联日程只发生在用户确认之后。

## 已消除的无效工作

- 删除了未被消费的 `needs_rich_answer` 规划字段。
- 删除运行时构造后立刻被覆盖的整段旧聚合规划提示词。
- 普通对话不再无条件加载 Workspace 和主动服务状态。
- 规划器超时不再开放全部工具和完整系统提示词。
- 已规划搜索、arXiv、附近地点和完整有序路线不再增加“复述固定 JSON”的模型轮次。
- 位置、路线和纯论文结果可由已验证结构化数据本地渲染，不再增加固定确认文案模型轮次。
- 后续问题、记忆提取、主动机会判断从“每轮三次模型任务”改为逐项动态启用，并统一关闭深度思考。

## 仍保留的必要边界

- 必要输入门与动态提示词选择已合并为一次 `SemanticPreflight`，加上能力规划共两次 Flash
  结构化调用。只有预检准备阻断用户时才增加一次独立审查：真实缺失在审查通过后短路，疑似误问
  在审查驳回后继续规划。
- 日程、会议、工作流、生图等自由参数仍需要一次受 schema 约束的 Flash 调用；Provider 和 Action 层会再次验证。
- 腾讯地点或路线服务不可用、浏览器拒绝定位、地点证据存在真实歧义或没有足够证据时，系统不能
  假装完成，只能用主动式卡片恢复；同一明确地标的多条 Provider 记录不视为真实歧义。
